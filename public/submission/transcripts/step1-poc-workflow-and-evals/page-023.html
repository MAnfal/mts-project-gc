export function stageFunnel(runs: Pick<RunRecord, "stages">[]) {
  const by = new Map<string, { ins: number[]; outs: number[]; ms: number[]; cost: number[] }>();
  for (const run of runs)
    for (const s of run.stages) {

You're right that the absolute counts invite the wrong question. The honest framing is the one from your RFC: precision and recall, against the targets. Recall: did we catch everything that matters? Precision: of what we show the GC, how much matters?

Setup Recall (target ≥ 90%) Precision (target ≥ 80%) What the GC sees each week
Sonnet · Jev · default prompt 98% ✓ 45% ✗ about 2.3 real items plus 2.8 noise
Sonnet · Jev · strict prompt 93% ✓ 79.6% (just under) about 2.2 real items plus 0.5 noise
Baseline 71% ✗ 79% misses about 1 in 3 real items

So the story is: the first version was noisy, the eval caught it, one prompt change fixed most of it, and we're 0.4 points short on precision. For a GC, a miss (a deadline nobody saw) costs far more than a false flag (a minute to dismiss). That's why recall is the hard floor and precision is the thing to tune.

Ideas for improving the system, ordered by value for money:

  1. Tune the Jev cut-off from data we already have (free). The traces hold every Jev probability, so I can replay thresholds against the key with no new runs, then pick the highest cut-off that keeps the filter's recall at about 98% or better.
  2. A "show me the obligation" check (about +$0.02 a run). For each kept item, a second LLM pass must quote the sentence that creates a duty for this company, and code checks that the quote exists, just like the date check. The heatmap says the biggest remaining failure is "mentions us, requires nothing" traps, and a required, verified quote targets exactly that.
  3. Deterministic demotion by document type (free). Meeting notices, paperwork renewals and corrections that change nothing are recognizable from the title and fields. Code can down-rank them before the LLM sees them.
  4. Majority vote on the filter (about +$0.15 a run). Run the LLM filter 3 times on the ~50 survivors and keep what at least 2 of 3 flag. That should improve both precision and the "same every run" score.
  5. The notice tier gap. Notices already in force (like the SNAP candy bans) should be "in force since", not Low.

How we'd evolve it: each idea becomes a new setup or prompt set in config, runs on the dev week first, and only counts as a win if it also holds on the held-out test week. A variant costs about $2.30 (18 runs at $0.13), and about $14 of the budget is left, so roughly 4–5 variants.

I'd start with #1 (free) and #2 (cheap, and the most direct attack on the trap problem). Want me to also switch the dashboard's headline to precision and recall against the targets?
