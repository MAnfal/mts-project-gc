Yes, evolving the system is the point of evals. The way to do it reliably is a loop, not a list of guesses:

   ┌──────────────────────────────────────────────────────────────────────────┐
   ▼                                                                          │
1. ERROR ANALYSIS     read every failure's trace, label WHY it failed          │
   (traces → buckets)   e.g. Jev dropped it · LLM misread scope · profile      │
                        unclear · key wrong · date/tier slip                   │
2. PICK THE BIGGEST   fix the largest bucket first (Pareto), one change only   │
3. CHANGE = CONFIG    a new prompt set / step / threshold / model-per-step     │
                        = a new setup in setups.yaml                           │
4. RUN ON DEV         same cases, compare against the current winner          │
5. CONFIRM ON TEST    must also improve on the held-out week, or it's overfit │
6. PROMOTE            new winner; every fixed failure becomes a regression case ┘

What makes this work rather than guesswork:

  • Error analysis comes from the traces, not intuition. Every miss and false flag has a full trace, so an LLM can do a first-pass labeling of failure causes and I check them. That's Hamel's open/axial coding. Today we're guessing that "mentions us, requires nothing" is the big bucket; this would count it.
  • Some failures will be the key's fault. The bucket "key is wrong or ambiguous" goes back to the blind reconcilers, not into the prompt. Otherwise we'd tune the system to match a bad answer.
  • The real constraint is statistical, not budget. With 14 rules that matter, 93% vs 98% recall is one rule, so we can't tell real gains from noise. Before tuning hard, the first spend should be more eval data: more weeks per company, aiming for 50+ rules that matter. Keys cost nothing (agents), and runs cost about $0.13 each. Then we show confidence ranges on the dashboard, as LMArena does.
  • Room beyond prompts:
  • Pipeline shape: an obligation-quote check, majority vote on the filter.
  • Model per step: a cheap model for filtering and a strong one for verifying, set in config.
  • Profile quality: the profile is a prompt too, so give it explicit scope.
  • Prompt search can be partly automated. An LLM proposes prompt edits from the failure buckets, they run on dev, and they're kept only if better. That's the idea behind DSPy/GEPA-style optimizers, but those are Python, so in TS it would be our own small loop. A human approves each promotion.

// Record one improvement iteration: the story (hypothesis, change, decision) + measured results + config snapshot.
//   npx tsx scripts/iteration.mts <data/iterations/<id>/spec.yaml>
// spec.yaml (hand-written): { id, title, date, suite, setup, comparedTo?, hypothesis, change, decision, notes? }
// Writes iteration.yaml next to it (spec + results computed from the suite) and config/ (snapshot of live config).
import fs from "node:fs";
import path from "node:path";
import YAML from "yaml";
import { arenaRuns } from "../src/lib/arena";
import { CONFIG_DIR, configHash } from "../src/lib/config";
import { suiteReport } from "../src/lib/suite";

const specPath = process.argv[2];
const dir = path.dirname(specPath);
const spec = YAML.parse(fs.readFileSync(specPath, "utf8")) as { id: string; suite: string; setup: string; comparedTo?: string } & Record<string, unknown>;
const report = suiteReport(await arenaRuns(spec.suite));
const pick = (key: string) => {
  const s = report.setups.find((x) => x.key === key);
  if (!s) throw new Error(`setup ${key} not in ${spec.suite}`);
  const sl = (k: string) => (s.slices[k] ? `${s.slices[k].correct}/${s.slices[k].total}` : null);
  const r2 = (x: number | null) => (x === null ? null : Math.round(x * 1000) / 1000);
  return {
    setup: key,
    label: s.label,
    runs: s.graded,
    recall: r2(s.metrics.recall),
    precision: r2(s.metrics.precision),
    trapAvoidance: r2(s.metrics.trapAvoidance),
    datesRight: r2(s.metrics.datesRight),
    judgePass: r2(s.metrics.judgePass),
    consistency: r2(s.metrics.consistency),
    score: r2(s.score),
    perRun: Object.fromEntries(Object.entries(s.countsPerRun).map(([k, v]) => [k, Math.round(v * 100) / 100])),
    devCasesRight: sl("split:dev"),
    testCasesRight: sl("split:test"),
    costPerRunUsd: Math.round(s.costPerRun * 1000) / 1000,
    secondsPerRun: s.msMean === null ? null : Math.round(s.msMean / 1000),
  };
};
const results = { candidate: pick(spec.setup), ...(spec.comparedTo ? { comparedTo: pick(spec.comparedTo) } : {}) };
const out = { ...spec, results, configHashAtRecord: configHash(), recordedAt: new Date().toISOString() };
fs.writeFileSync(path.join(dir, "iteration.yaml"), `# Generated by scripts/iteration.mts from spec.yaml — edit spec.yaml, then re-run.\n${YAML.stringify(out, { lineWidth: 0 })}`);
fs.rmSync(path.join(dir, "config"), { recursive: true, force: true });
fs.cpSync(CONFIG_DIR, path.join(dir, "config"), { recursive: true, filter: (src) => !src.includes(`${path.sep}weeks${path.sep}`) && !src.endsWith(`${path.sep}weeks`) });
console.log(`recorded ${spec.id}: ${results.candidate.label} recall ${results.candidate.recall} precision ${results.candidate.precision} score ${results.candidate.score}`);
