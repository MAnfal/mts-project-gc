PRINCIPLES 1. Use deterministic graders where possible, LLM graders where necessary, and humans to validate them (A). 2. Grade the outcome (report.json), not the path. Rigid step checks are brittle (A). 3. Test both should and should-not. A says "One-sided evals create one-sided optimization", so avoid class-imbalanced sets. 4. Start with "20-50 simple tasks drawn from real failures". Early changes have large effects, so small sets work (A). D adds "prioritize volume over quality". 5. A good task is one where two experts would reach the same verdict independently. Ambiguity turns into metric noise (A). 6. Capability evals are for hill-climbing. Regression evals should pass about 100%, and saturated capability tasks graduate into them (A). 7. pass^k means all k trials succeed. Our "tier identical across 3 runs" target is already pass^3 (my mapping onto A). 8. Score binary pass/fail with a critique, not 1-5 scales (HJ, EP). 9. Calibrate each judge against human labels using TPR/TNR on dev and test splits, with 30-50 Pass and 30-50 Fail in each (HF). Add Cohen's kappa (EP). Give the judge an "Unknown" exit (A). 10. For classification, report precision, recall, PR-AUC and the separation of score distributions (EE). 11. Read transcripts; failures should "seem fair" (A). Don't outsource labeling (HF).

SUITE (a) Components - Jev filter. Data: {doc, profile, label}. Metrics: recall at the threshold, PR curve with a threshold sweep, score histograms by label (EE). My inference: treat it as recall-critical (≥0.98), since a doc it drops can't be recovered later. - LLM filter. Same rows, restricted to docs Jev passed.
